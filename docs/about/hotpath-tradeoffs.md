# Hot-path optimization tradeoffs

All figures are paired microbenchmark or workload observations on
Go 1.27.2/linux-amd64, i9-13900K, one Go P without CPU affinity. Values are
medians, not end-to-end throughput or statistical significance claims.
Originals remain in tests and benchmarks. Each optimization below links
to its separate commit with the problem, workload, measurements and costs.

See the [latest benchmark results and validation](hotpath-benchmarks.md)
and [current/original source comparisons](hotpath-code.md).

| Optimization                                                                                   | Useful workload result                                                                               | Cost / boundary                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Per-node peer-map matcher reuse](https://github.com/kradalby/headscale/commit/41a67e23f)      | 1000 nodes/10 owners: 771 → 71.7 ms, 10.8x                                                           | Dense one-owner output: 732 → 363 ms, 2x; output remains quadratic; rule pooling adds temporary storage                                                                                           |
| [Grant destination resolution reuse](https://github.com/kradalby/headscale/commit/945f1dfbe)   | 1000-node repeated large group: 17.10 → 6.64 ms, 2.6x; four real resolutions → one                   | Cache only lasts one compilation; no benefit without reuse                                                                                                                                        |
| [Plain policy destination matching](https://github.com/kradalby/headscale/commit/8b3bbace0)    | 4096 matches: 1.66 → 0.43 ms, 3.9x                                                                   | Fallback-only control ~3% slower; uncommon syntax retains original parser                                                                                                                         |
| [IP allocator membership map](https://github.com/kradalby/headscale/commit/c4308addf)          | Fixed-512 fragmented 10000-address Next: 6.006 ms → 421 ns; 1000-node sparse backfill: 603 → 56.7 ms | Adaptive population windows are excluded from published comparisons. Loading 10000 IPv4+IPv6 pairs: 30.82 → 32.57 ms (+6%), +2.62 MB allocated. After-GC allocator retention ~0.48 KiB → 1.25 MiB |
| [Primary-route projection](https://github.com/kradalby/headscale/commit/0bda40788)             | 2048-prefix lookup: 19.13 us → 194 ns; election+617 lookups: 2.91 → 0.947 ms                         | Election alone 807 → 941 us (+17%), +~70 KB and 514 allocations; projection retains slices; each read clones                                                                                      |
| [Lazy peer membership](https://github.com/kradalby/headscale/commit/5b8b3262c)                 | Warm dense 128-recipient/eight-patch fanout: 3.12 ms → 15.7 us                                       | Cold: 3.105 → 3.691 ms; relation rebuild+fanout: 8.391 → 8.722 ms. Cached 128 dense rows retain 1047552 ID bytes, excluding metadata                                                              |
| [Wire framing](https://github.com/kradalby/headscale/commit/2814f6d9e)                         | 128-peer compressed allocated bytes: 125956 → 89475 (-29%)                                           | One extra allocation in this fixture; modest CPU difference. Rejected full-JSON reservation regressed repetitive payload memory                                                                   |
| [Lazy user fallback](https://github.com/kradalby/headscale/commit/cd7fa8fdf)                   | Named profile/ID1000: 33.91 → 10.47 ns; two allocations → zero                                       | Numeric-only fallback still formats an ID                                                                                                                                                         |
| [Profile value map](https://github.com/kradalby/headscale/commit/cd4ed8c9f)                    | 8192 peers/one owner: 157.37 → 40.59 us; 8198 → five allocations                                     | Uses current name helpers on both sides. Frozen full-generator adapter timing is excluded from attribution                                                                                        |
| [Broadcast ingress](https://github.com/kradalby/headscale/commit/e5a172f38)                    | 10000 recipients/64 changes: 146.21 → 40.82 ms; 324.18 → 108.82 MB allocated                         | Enqueue only; exactly 640000 pending changes checked/drained outside timing; owned per-recipient copies remain                                                                                    |
| [Ready-channel send](https://github.com/kradalby/headscale/commit/f406bef29)                   | Buffered send+drain: 409 → 79 ns; three allocations → zero                                           | Blocked control still ~50 ms and six allocations; active reader about 2x                                                                                                                          |
| [Ephemeral timer callbacks](https://github.com/kradalby/headscale/commit/497bdab68)            | 10000 pending timers: 6.06 → 4.10 ms; waiting goroutines 10000 → zero; heap 12.68 → 3.55 MB          | One collector consumer remains; expiry launches callbacks. One-node pending 0.98 → 1.97 us, one-node burst 3.72 → 8.82 us                                                                         |
| [Revoked-key savepoints](https://github.com/kradalby/headscale/commit/2e4e884b1)               | 1000 SQLite keys: 53.95 → 30.12 ms; SQL 3001 → 2001 statements                                       | Zero keys adds 240 B/two allocations; one-key rollback 134 → 278 us in three samples. PostgreSQL correctness, not performance, measured                                                           |
| [Route advertiser sorting](https://github.com/kradalby/headscale/commit/91ba190c4)             | 10000 nodes/two routers HA: 1.012 → 0.180 ms                                                         | Dense election ~4% slower; prefix-heavy HA 593 → 655 us with overlapping timings. Whole sparse transition only ~3% faster                                                                         |
| [Native STUN addresses](https://github.com/kradalby/headscale/commit/d00f135bf)                | Three → two allocations per real UDP exchange                                                        | No CPU gain established; IPv4/IPv6/mapped sockets tested; actual scoped link-local roundtrip omitted                                                                                              |
| [Selected capability snapshots](https://github.com/kradalby/headscale/commit/60d3eb282)        | 10000 attributed nodes, one peer rendered: 373.9 → 3.02 us, 124x; eight peers: 383.4 → 11.70 us, 33x | Full peer rendering 16.30 → 16.32 ms; bulk copy retained when smaller; no permanent index                                                                                                         |
| [Call-local SSH source reuse](https://github.com/kradalby/headscale/commit/d3d8c583e)          | 256 nodes/32 repeated-source rules: 21.52 → 6.18 ms, 3.48x                                           | Unique small 103.1 → 110.6 us (+7.2%); unique dense ~2% slower; cache dies after call                                                                                                             |
| [Accepted DNS hash check](https://github.com/kradalby/headscale/commit/00065edcc)              | Unchanged 10000 records: JSON 8.65x, HuJSON 40.3x, YAML 101.4x                                       | Every event still reads/hashes file; changed-event controls similar; event frequency unmeasured                                                                                                   |
| [Symmetric-visibility assertion index](https://github.com/kradalby/headscale/commit/e38b62bcf) | Dense 512-client assertion 266.04 → 31.97 ms, 8.32x                                                  | Test harness only; 14.06 MB temporary; small cases scan; sparse 512 ~5% slower/zero allocation; no permanent index                                                                                |

Scheduler isolation, disconnected-recipient generation, expiry clock checks
and admin-list sorting remain unimplemented candidates requiring their own
baseline and proof. The
[registration Hostinfo clone](https://github.com/kradalby/headscale/commit/f150023f7)
is a separate race fix, not a speedup claim.
